Act09

LAB: TRAVERSAL SEQUENCES STRIPPED NON-RECURSIVELY

Abrir PDF ↗

Previsualización de la Investigación

OBJETIVO

El objetivo de este laboratorio es explotar una vulnerabilidad de File Path Traversal (también conocido como Directory Traversal) en la sección de visualización de imágenes de productos. La aplicación implementa un mecanismo de defensa que elimina las secuencias de escape de directorios (../); sin embargo, lo hace de manera no recursiva (solo realiza un único reemplazo). El reto consiste en burlar este filtro usando secuencias anidadas (por ejemplo, ....//) para recuperar el contenido sensible de /etc/passwd.

AMBIENTE DE LABORATORIO

Iniciamos Burp Suite y capturamos el tráfico generado por el navegador. Al inspeccionar la tienda, observamos que las imágenes de producto se solicitan mediante peticiones HTTP GET con un parámetro filename (por ejemplo, filename=blog.png).

Enviamos la petición al módulo Repeater para realizar pruebas iterativas sin afectar la navegación principal.

Probamos rutas como ./../etc/passwd y observamos que la aplicación responde con Bad Request o limpia la entrada. A continuación probamos secuencias anidadas como ....//....//....//etc/passwd, que al pasar por el filtro no recursivo se transforman en ../../../etc/passwd y permiten el acceso.

ANÁLISIS DE LA VULNERABILIDAD Y FORMA DE RESOLUCIÓN

  1. Comportamiento del filtro básico: El servidor bloquea o limpia rutas directas como /etc/passwd o secuencias estándar ../../../etc/passwd porque detecta y remueve la subcadena ../.
  2. Explotación por eliminación no recursiva: El filtro realiza un único reemplazo de la secuencia prohibida. Si se envían secuencias anidadas (por ejemplo ....//), la eliminación única deja caracteres que, al concatenarse, forman una secuencia válida ../.
  3. Ejemplo de bypass: Entrada enviada: ....//....//....//etc/passwd
    Tras la limpieza no recursiva, el resultado concatenado es: ../../../etc/passwd, permitiendo el acceso al archivo.
  4. Mitigación recomendada: Evitar usar entradas de usuario directamente en APIs del sistema de archivos; emplear listas blancas (whitelisting) y funciones de canonicalización de rutas que validen que el archivo final esté dentro del directorio autorizado.

COMANDOS Y HERRAMIENTAS UTILIZADAS

  • Burp Suite – Proxy (Intercept ON): Captura y modificación de peticiones HTTP; uso de Forward para permitir la carga de la página.
  • Burp Repeater: Pruebas iterativas sobre la misma petición sin alterar la navegación principal.
  • curl: Verificación rápida de rutas y pruebas desde línea de comandos (ejemplo de uso en laboratorio).
  • Observación de logs: Revisión de registros del servidor para corroborar accesos a recursos sensibles.
  • Manipulación del parámetro GET (filename): Sustitución del nombre de la imagen por payloads anidados (....//) para evadir el filtro no recursivo.

RESULTADOS

Se identificó que la aplicación implementa una sanitización débil basada en reemplazos simples que operan de forma no recursiva. El uso de payloads anidados (....//) permite superar el bloqueo de secuencias simples (../) y acceder al archivo /etc/passwd, confirmando la vulnerabilidad.

CONCLUSIONES

  • Debilidad de filtros por reemplazo único: Las sanitizaciones que eliminan cadenas prohibidas sin iterar hasta que no queden coincidencias son vulnerables a técnicas de anidación.
  • Valor de Burp Repeater: Facilita la iteración rápida de payloads para comprobar fallos lógicos en mecanismos de defensa.
  • Mitigación adecuada: Implementar canonicalización de rutas, whitelisting y validaciones que garanticen que la ruta final reside dentro del directorio permitido.
